## Lessons (สำคัญ)

### 1. Test suite ของ synapse พ่วง wipe vault จริง
`conftest.py` ของ suite ชี้ `DATABASE_URL` default ไป `localhost:5432/synapse` =
**production vault DB ตัวเดียวกับที่ container ใช้** และ `clean_pg` fixture
DELETE ทุกตารางก่อนแต่ละเทสต์ การรัน "pytest tests/" ปกติ = ลบ vault ทั้งหมด

**ทางออกที่ใช้วันนี้**: สร้าง throwaway DB (`synapse_test_run`) + สร้าง pgvector
extension ก่อน + `DATABASE_URL=... pytest tests/` — 657 passed โดย vault ไม่โดนแตะ
**ควรทำถาวร**: เปลี่ยน default TEST_DB_URL ของ conftest ไปที่ DB เทสต์เฉพาะ
หรือ fail-fast ถ้าชี้ไปที่ DB ที่มีเอกสารจริง (บันทึกเป็น ISSUE ใหม่)

### 2. schema.sql greenfield init พังมาก่อนโดยไม่มีใครเห็น
Migrations (DO block + ALTER knowledge_documents) เรียง **ก่อน** CREATE TABLE
ตารางนั้น และ fresh CREATE TABLE ไม่มีคอลัมน์ `metadata`/`archived_at` ที่ index
ในไฟล์เดียวกันอ้างถึง — รันบน DB ใหม่ = error ตั้งแต่ statement แรกๆ
Production รอดเพราะ migrate ไปก่อนหน้านั้นแล้ว เลยไม่มีใครเจอจนวันนี้ที่ต้องสร้าง
fresh DB เพื่อทดสอบ CPT
**Fix**: ย้าย migrations ไปท้ายไฟล์ + เพิ่มคอลัมน์ใน CREATE TABLE (idempotent ทั้งสอง path)

### 3. pgvector extension ต้องมีก่อน pool connect
`PgStore.connect()` สร้าง pool min_size=2 พร้อม register vector codec ทันที —
ถ้า DB ยังไม่มี extension จะพังด้วย `unknown type: public.vector` **ก่อน**
`init_schema()` จะได้สร้าง extension เสียอีก การ init DB ใหม่ต้อง
`CREATE EXTENSION vector` ก่อนเรียก connect เสมอ

### 4. ระวังคำสั่งที่แอบ wipe
คำสั่งงานบอก "ห้าม wipe DB" ไว้ถูกต้อง — แต่อันตรายจริงอยู่ที่ test infrastructure
ที่ wipe ให้เองเงียบๆ ไม่ใช่คำสั่งที่มองเห็น ตรวจ fixture ก่อนรัน suite ทุกครั้ง
ที่ DB เป็นของจริง
